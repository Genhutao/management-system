# 学管会综合管理系统 · 功能严格测试用例集

> 依据：`API接口文档.md`（2026-09 版）+ 2026-09-26 对外合规审计结论。
> 适用版本：`backend/cmd/server` 当前 main 分支。
> 用例原则：**严格断言**——每个用例给出必须逐字/逐值核对的状态码、错误文案或字段值；"大概成功"不算通过。
>
> 优先级：P0 = 主干与安全边界，每轮发布必跑；P1 = 常规回归；P2 = 健壮性/容错。

---

## 0. 测试环境与通用约定

| 项 | 要求 |
|---|---|
| 部署形态 | 与生产一致（容器化 + `JWT_SECRET`/`CRYPTO_SECRET` 显式注入；`GIN_MODE=release`） |
| 测试库 | 独立 SQLite 文件（`DB_PATH` 指向临时文件），每轮清库重置种子数据 |
| 账号 | 每角色至少 2 个：`tech_admin`、`minister`（技术部+非技术部各1）、`member`、`dorm_manager`（楼栋A、楼栋B各1）、`viewer_export`、`disabled` 账号 1 个 |
| 钟点控制 | 涉及时段判定（today-tasks / slot-notice / sweep-missed）的用例需可 mock 服务器时间或临时改配置 |
| 断言基准 | HTTP 状态码 **且** 响应 JSON 键值；写操作还需回查数据库（`operation_logs`、`users.total_score` 等）落库结果 |

通用安全前置用例（每次会话开始先跑）：

| 编号 | 用例 | 预期 |
|---|---|---|
| TC-G-001 | 未带凭据请求任一受保护接口（如 `GET /api/v1/deductions`） | `401`，body `{"error":"请先登录系统"}` |
| TC-G-002 | 带 7 天前签发的过期 token 请求 | `401`，且响应头 Set-Cookie 清除 `xgh_session` |
| TC-G-003 | 带伪造签名 token（改 payload 不改签名） | `401`，文案 `登录已失效或无效令牌…` |
| TC-G-004 | OPTIONS 预检请求（任意 Origin） | `204`；`Access-Control-Allow-Origin` **不出现**，除非该 Origin 在 `ALLOWED_ORIGINS` |
| TC-G-005 | `ALLOWED_ORIGINS` 外的 Origin 发起带凭据的 GET | 响应无 `Access-Control-Allow-*` 头 |
| TC-G-006 | 路径参数含 `../`、`%2e%2e%2f`、Unicode 归一化变体（如 `/api/v1/tech/db/tables/../users`） | `404/400`，绝不 200；不得穿透表白名单 |
| TC-G-007 | JSON body 超大（>8MB）POST 到公开接口 | `400` 或 413，进程不 crash、无 panic 堆栈 |
| TC-G-008 | 全部接口响应头无 `X-Powered-By`/框架版本泄露；`Server` 头不暴露 Gin 版本 | 通过 |

### 1.1 账号密码登录 `POST /auth/login`

| TC-AUTH-002 | P0 | — | 错误密码 ×1 | `401`，文案**逐字**为 `账号或密码错误`（不得区分账号不存在/密码错误） |

## 执行说明

3. 涉及外部 AI 的用例（TC-UP-003、TC-SCH-012/013、TC-WEL-004~007）用 mock 上游（本地 HTTP 假端点 + 白名单放行测试域）保证可重复。
4. 测试产生的含 PII 数据留在测试库，跑完即删——测试环境同样适用"含 PII 禁推"约定。
